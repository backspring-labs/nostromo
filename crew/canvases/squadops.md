## What SquadOps is

**SquadOps is the owner's AI agent framework for software development**, a separate product in its
own repository (`backspring-labs/squad-ops`).
- **The squad.** Six agents build working applications from a PRD: Max (lead), Nat (strategy), Neo
  (development), Bob (builder), Eve (QA) and Data (analytics). They run on the Spark's local model.
- **Cycles.** Work happens in cycles, made of runs and tasks, with gates where a plan or an increment
  is ruled on.
- **Campaigns.** A campaign evolves one app across cycles. It opens with a calibration cycle. Each
  increment is proposed, ruled at its gate, built, and accepted only if everything accepted before
  still passes.
- **Its own governance:** SIPs, release plans, pre-registered verification sets, releases.

**Nostromo is not SquadOps.** Nostromo is this crew: it improves the framework and supervises its
campaigns. The **squad** is SquadOps's agents; the **crew** is us. `campaignctl`, the broker and
the review workers are Nostromo's interface *to* SquadOps.

## How the crew works

- **Owner decides:** architecture, scope, money, policy exceptions, anything irreversible. Escalate
  decisions, not chores.
- **Campaigns:**
  - Mother launches only owner-approved definitions, through `campaignctl`.
  - Ripley rules on plan and increment gates.
  - Dallas independently reviews Ripley's exact decision.
  - Brett supplies deterministic evidence. Parker implements.
  - The broker verifies every signed decision.
- **Records:**
  - SquadOps owns campaign state, gates, ledgers and artifacts.
  - GitHub owns code and its reviews.
  - Buzz owns coordination, signed decisions and closing reports.
- **Every turn is paid.** Mention someone only when they must act. One work item, one thread. Never
  relay what is already in the thread.
- **Deploys:** merge to main, then `deploy-spark.sh`. Root steps run from a fresh root-owned clone.

## Glossary

- **Cycle / run / task.** A cycle is one SquadOps work unit. A run is one attempt at it. Tasks are
  the agents' steps.
- **Gate.** A ruling point: `progress_plan_review` (the plan) or `progress_increment_ruling` (an
  increment).
- **Increment.** One accepted change to the campaign's app.
- **Accumulated acceptance.** Everything accepted before must still pass.
- **Calibration cycle.** A campaign's first cycle, which frames the app and its baseline.
- **Broker.** Nostromo's service holding SquadOps credentials; `campaignctl` talks to it.
- **Shared / exclusive inference.** Ordinary campaigns share the TensorFold engine with Mother and
  Brett. Counted verification is exclusive: it stops the local harnesses outside a leased window.
- **Release.** One merged Nostromo commit, live on the Spark under `/opt/nostromo/current`.
- **Crew / squad / team.** The crew is Nostromo's, the squad is SquadOps's, a team is Buzz's.
